# KAVASI → Supabase + Vercel Deployment Guide

## Step 1 — Create a Supabase Project

1. Go to **[supabase.com](https://supabase.com)** → **Sign up / Log in**
2. Click **New Project** → pick an organisation → fill in:
   - **Name**: `kavasi-db`
   - **Database password**: choose something strong (save it!)
   - **Region**: closest to your users (e.g. `ap-south-1` for India)
3. Wait ~1 minute for the project to provision.

---

## Step 2 — Run the Schema

1. In your Supabase project, click **SQL Editor** in the left sidebar
2. Click **New Query**
3. Open `supabase-schema.sql` from your project root and **paste the entire file** into the editor
4. Click **Run** (▶)

This creates all tables (`Admins`, `Contacts`, `Projects`, `TeamMembers`, `Jobs`, `Applicants`) and inserts the seed data including your admin account.

> **Admin login:** `admin@kavasi.com` / password: `ewqasdcxz`

---

## Step 3 — Get Your API Keys

1. In your Supabase project → **Project Settings** → **API**
2. Copy:
   - **Project URL** → this is your `NEXT_PUBLIC_SUPABASE_URL`
   - **`anon` / `public` key** → this is your `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   - **`service_role` / `secret` key** → this is your `SUPABASE_SERVICE_ROLE_KEY`

## Step 5 — Disable Row Level Security (RLS) — Required!

By default, Supabase enables RLS which blocks all queries. Since you're using the `service_role` key on the server, you need to either disable RLS or add a policy.

**Easiest option — disable RLS on all tables** (fine because all access is server-side):

In Supabase → **Table Editor** → for each table (`Admins`, `Contacts`, `Projects`, `TeamMembers`, `Jobs`, `Applicants`) → **Auth Policies** tab → toggle **Row Level Security** to **OFF**.

Or run this in SQL Editor:
```sql
ALTER TABLE "Admins" DISABLE ROW LEVEL SECURITY;
ALTER TABLE "Contacts" DISABLE ROW LEVEL SECURITY;
ALTER TABLE "Projects" DISABLE ROW LEVEL SECURITY;
ALTER TABLE "TeamMembers" DISABLE ROW LEVEL SECURITY;
ALTER TABLE "Jobs" DISABLE ROW LEVEL SECURITY;
ALTER TABLE "Applicants" DISABLE ROW LEVEL SECURITY;
```

## Step 6 — Deploy to Vercel

### Option A — From Vercel Dashboard (Recommended)

1. Push your code to **GitHub**:
   ```powershell
   git add .
   git commit -m "chore: migrate to Supabase"
   git push origin main
   ```
2. Go to **[vercel.com](https://vercel.com)** → **Add New Project** → import your GitHub repo
3. Vercel auto-detects Next.js. Click **Deploy** (first deploy will fail on env vars — that's OK)
4. Once deployed, go to **Project → Settings → Environment Variables** and add all 8 variables from your `.env.local`:
   | Key | Value |
   |-----|-------|
   | `NEXT_PUBLIC_SUPABASE_URL` | `https://....supabase.co` |
   | `NEXT_PUBLIC_SUPABASE_ANON_KEY` | `eyJ...` |
   | `SUPABASE_SERVICE_ROLE_KEY` | `eyJ...` |
   | `JWT_SECRET` | `your-secret` |
   | `SMTP_HOST` | `smtp.gmail.com` |
   | `SMTP_PORT` | `587` |
   | `SMTP_USER` | `you@gmail.com` |
   | `SMTP_PASS` | `your-app-password` |
   | `ADMIN_EMAIL` | `admin@kavasi.com` |
5. Go to **Deployments → Redeploy** → the app is live!

### Option B — Vercel CLI

```powershell
npm i -g vercel
vercel login
vercel --prod
```
Then add env vars in the Vercel dashboard as above.

## Application ID Format

When someone applies for a job, the application ID is **automatically generated by the database**:

- Format: `KAVASI-000001`, `KAVASI-000002`, …
- Powered by a PostgreSQL **sequence** (`applicant_seq`) — guaranteed unique and always incrementing
- No app-side generation needed — it comes back from the DB insert response

## Troubleshooting

| Problem | Fix |
|---------|-----|
| `Invalid API key` errors | Check your Supabase env vars — copy from Settings > API |
| Tables return empty arrays | Run RLS disable SQL from Step 5 |
| `relation does not exist` error | Re-run `supabase-schema.sql` in SQL Editor |
| Email not sending | Configure real SMTP credentials (Gmail App Password) |
| Login fails | The admin seed row must exist — check Admins table in Supabase Table Editor |
